# leyes-chile

The **pipeline** that builds a git history of the Chilean Constitution and
major Códigos, sourced entirely from [BCN's LeyChile](https://www.leychile.cl)
public data — no LLMs, no manual transcription.

This repo is tooling only. The actual deliverable — `leyes/*.md` and the
commit history that *is* their amendment history (one commit per historical
version, real effective date, real enacting norm, real signer/author where
BCN has the data) — is written into a separate sibling repo,
`../leychile/` (`DATA_REPO_ROOT` in `build_repo.py`), so the law data can be
published/shared independently of the pipeline code.

## What's here

- `src/leyeschile/` — the pipeline. See module docstrings for the exact BCN
  endpoints each part uses and how they were verified.
- `config/targets.yaml` — the list of tracked documents (slug + BCN
  `idNorma`), generated by `discover.py`.
- `cache/` (gitignored) — every raw HTTP response ever fetched, cached
  forever by URL. Re-running the pipeline never re-hits an already-fetched
  URL.
- `state.json` (gitignored) — resumability checkpoint: which
  `(idNorma, version date)` pairs have already been committed **to
  `../leychile/`**.

Not here: `../leychile/leyes/*.md` and its git history — that's in the data
repo.

## Auditability

Every generated file carries a YAML front-matter block naming the exact
BCN source URL, `idNorma`, version date, and fetch timestamp used to
produce it:

```yaml
---
source_url: https://nuevo.leychile.cl/servicios/Navegar/get_norma_json?idNorma=...&idVersion=...
id_norma: 172986
version_date: 2015-03-11
fetched_at: 2026-08-02T23:40:02.989982+00:00
titulo_norma: "..."
compuesto: LEY-...
organismos: [...]
fecha_publicacion_original: ...
---
```

Every commit message also names the amending norm and repeats the source
URL for that specific snapshot, so any commit can be independently
re-verified against the live BCN API.

## How the data is sourced

BCN's *documented* public API (`leychile.cl/esquemas/accesoLeyesChilenas4.pdf`)
turned out not to support fetching a norm's text as of an arbitrary past
date — its `fechaVersion` parameter is silently ignored. The pipeline
instead uses BCN's own web app's internal (undocumented, but public,
same-origin) JSON services, found by driving a real browser to
leychile.cl and inspecting its network calls:

| Purpose | Endpoint |
|---|---|
| Amendment timeline for a norm | `nuevo.leychile.cl/servicios/Consulta/get_versiones?idNorma=<id>` |
| Full text as of a specific date | `nuevo.leychile.cl/servicios/Navegar/get_norma_json?idNorma=<id>&idVersion=<date>` |
| Named congressional authors (if any) | `nuevo.leychile.cl/servicios/Navegar/get_autores_de_la_ley?idNorma=<id>` |
| Canonical list of the 15 official Códigos | `nuevo.leychile.cl/servicios/Consulta/getCodigos` |

All three "point-in-time" endpoints were verified against real data before
being relied on (see `src/leyeschile/versions.py` and `norma_json.py`
docstrings) — dates were checked against known amendment history and
confirmed to return genuinely different, correctly-sized content, not a
parameter that's silently ignored.

Commit authorship combines two real sources so both "who wrote it" and "who
signed it into law" are credited when available:

- **Named congressional authors** from `get_autores_de_la_ley`, populated
  only for laws that began as a parliamentary "moción".
- **Promulgación signers** (`src/leyeschile/promulgacion.py`), parsed
  straight out of the norm's own text — every norm ends with a signature
  block naming the President (or, for 1973-1990 decree-laws, the Junta de
  Gobierno) and a Minister, e.g. Código Aeronáutico's real footer:
  `AUGUSTO PINOCHET UGARTE, Capitán General, Presidente de la República.-
  Hugo Rosende Subiabre, Ministro de Justicia`. This is almost always
  present, unlike `get_autores_de_la_ley`.

The primary git author is the first named congressional author if any
exist, else the promulgación's President/Junta signer, else the issuing
`organismo`. Everyone else found (remaining named authors, the
promulgación signer(s) when a congressional author was primary) is added
as `Co-authored-by:` trailers, so a moción law credits its deputies *and*
the President who signed it, in the same commit. There's no real public
email for historical legislators/officials, so a clearly-synthetic
placeholder address is used (`...@sourced-from-bcn.leychile.invalid`); the
point is attribution and audit, not a working mailbox.

## Running it

```
python3 -m venv .venv && .venv/bin/pip install -e .

# the data repo must exist and be a git repo before running build_repo
mkdir -p ../leychile && git -C ../leychile init

# (re)build config/targets.yaml from BCN's canonical Código list + Constitution
.venv/bin/python -m leyeschile.discover

# build/continue the commit history in ../leychile - safe to stop and re-run any time
.venv/bin/python -m leyeschile.build_repo
```

**BCN rate-limits aggressively** (observed `HTTP 429` after a handful of
requests during development). `build_repo` paces requests conservatively
(6s minimum between real HTTP calls) and caches every response to disk, but
building the full history of documents amended hundreds of times over
decades (Código Civil, Código Penal, ...) is expected to take a long
time — run it in the background and let it resume across multiple
sessions via `state.json`.
